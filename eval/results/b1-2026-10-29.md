## Method notes (read before quoting any number)

- t1–t4: `eval/run-bench.sh setup` (fixture at fixed start commit
  `2e583970fb952158ad83617fe436534abd38295d`; pack/gate arms deploy
  `--profile full`; gate arm adds a pass-gate item whose verification
  command IS the task acceptance command). Executors are fresh
  subagent sessions, one per run, never reused.
- t5–t8: `eval/bench/prep.py` (run dir + CLAIM footer + manifest
  under `<root>/_manifests/`); verdicts from `eval/bench/evaluate.py`
  JSON (`tests_pass`, `tests_intact`, extras, `accepted`).
  prep.py nests run dirs as `<root>/<task>/<arm>/r<N>`; each dir was
  moved to the flat `<task>__<arm>__r<N>` name after prep (manifests
  hold hashes only, so the move does not affect scoring).
- Pack definition differs by family (t1–t4 pack = `--profile full`
  deploy; t5–t8 pack = 3-skill kit). Pack numbers are reported per
  family, never pooled across families. dist-slim is EXCLUDED.
- **Deviation from the parent task text, recorded honestly:**
  `run-bench.sh record` was NOT used: it writes to
  `eval/results/<task>_<arm>_rep<n>.json`, which are exactly the
  baseline record filenames — running it would overwrite the 36
  baseline records and violate the single-file boundary (only this
  file may change). t1–t4 verdicts instead run the identical
  acceptance commands from `run-bench.sh`'s `acceptance()` directly
  in the run dir. All B1 metrics live in this file only.
- False completion, per the pre-registration: executor claims done
  but the verdict fails (t1–t4: acceptance fails after a done
  claim; t5–t8: `tests_pass` false after a done claim, or
  `tests_intact` false). Where `accepted` is false ONLY via extras
  (tests pass, tests intact), that run is flagged `extras-only` and
  counted BOTH ways in the sensitivity note — the decision rules use
  the pre-registration-literal count.
- Duration = wall clock from `setup`/`prep` completion to the
  executor's final message. Verify attempts = times the executor ran
  the acceptance/verify command (self-reported in its final message).
  Interventions = 0 for all subagent runs by construction (no
  coordinator contact mid-run); any executor-reported blocker is
  noted instead.
- BLOCKED = run could not start (infra failure, BUDGET STOP), never
  pass/fail. Stop rule: blocked > 10% of 72 (i.e. 8+) → inconclusive.
- Quota guard: `subscription-status status` before each batch; stop
  if free-weekly usage exceeds 80%. Quota at start: 23%, resets
  Nov 4 21:48 CST. Cost ledger: no ledger file at start, so no
  BUDGET STOP expected (setup still consults `cost.py check`).
