## 1. 产品概述 / Overview

### 1.1 背景

公司内部 5 个研发团队目前用电子表格 + 即时消息管理任务，存在三个核心痛点：

1. 任务状态不透明：负责人每周手动汇总进度，信息滞后 2-3 天；
2. 优先级冲突：跨团队协作时无人统一排期，返工率约 15%；
3. 历史不可追溯：需求变更只在聊天记录里，复盘时找不到依据。

### 1.2 产品定位

一款轻量团队任务看板，面向 10-50 人规模的研发团队，提供**可视化任务流转**与**跨团队协同**能力。不做重型项目管理（如甘特图、资源 leveling），专注"今天做什么、谁在做、卡在哪里"。

### 1.3 目标用户

| 用户角色 | 规模 | 使用场景 | 核心诉求 |
|---|---|---|---|
| 一线开发 | 约 30 人 | 每日更新任务状态、查看分配 | 操作快（< 3 次点击完成状态流转） |
| 技术组长 | 5 人 | 排期、分配、跟进阻塞 | 一眼看到团队瓶颈 |
| 项目经理 | 2 人 | 跨团队协调、周报 | 自动生成进度数据 |

### 1.4 成功指标

| 指标 | 基线 | 目标（上线 3 个月） | 测量方式 |
|---|---|---|---|
| 周报准备时长 | 2 小时/人 | < 15 分钟 | 用户访谈 |
| 任务状态滞后 | 2-3 天 | < 4 小时 | 系统日志抽样 |
| 周活跃用户占比 | — | ≥ 80% | 埋点 |

## 2. 产品架构 / Product Architecture

### 2.1 总体架构

```text
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Web 前端    │────▶│  API 服务   │────▶│  PostgreSQL │
│ (React SPA) │◀────│ (REST)      │◀────│  数据库     │
└─────────────┘     └──────┬──────┘     └─────────────┘
                           │ WebSocket
                           ▼
                    ┌─────────────┐
                    │ 实时推送服务 │
                    └─────────────┘
```

- **前端**：React SPA，负责看板渲染与交互；
- **API 服务**：REST 接口，任务 CRUD、权限、统计；
- **实时推送**：WebSocket，看板变更即时同步到所有在线成员；
- **数据库**：PostgreSQL，任务、用户、团队、操作日志。

### 2.2 模块划分

| 模块 | 职责 | 对外接口 |
|---|---|---|
| 任务管理 | 任务 CRUD、状态流转、标签 | `TaskService` |
| 看板视图 | 列配置、拖拽、过滤 | `BoardView` 组件 |
| 协作 | 评论、@提及、通知 | `NotificationService` |
| 统计 | 燃尽图、工作量 | `ReportService` |
| 权限 | 团队/角色/任务可见性 | `AuthService` |

## 3. 功能规格 / Feature Specifications

### F-001 看板拖拽流转

- **功能描述**：用户可将任务卡片在看板列之间拖拽，松手即完成状态变更。
- **输入**：拖拽手势（源列、目标列、任务 ID）。
- **输出**：任务状态更新 + 操作日志 + WebSocket 推送给同看板在线成员。
- **前置条件**：用户对该任务有编辑权限；目标列是合法流转目标（见状态机）。
- **业务规则**：
  - BR-001：状态流转必须沿 `待办 → 进行中 → 待评审 → 已完成` 单向推进，不允许跳列；
  - BR-002：拖入"已完成"列时，若任务有关联未关闭子任务，弹出确认框；
  - BR-003：每次流转自动记录操作人 + 时间戳，不可编辑。
- **异常处理**：网络中断时本地暂存，恢复后自动重试并提示"已同步 N 条变更"。

### F-002 任务快速创建

- **功能描述**：在看板列底部点击"+"，输入标题回车即创建任务（标题必填，其他字段可后补）。
- **输入**：任务标题（必填，≤ 100 字）、所属列（默认为点击的列）。
- **输出**：新任务卡片出现在列顶部，状态为该列对应状态。
- **前置条件**：用户是看板成员。
- **业务规则**：
  - BR-004：标题为空时禁止提交，输入框抖动提示；
  - BR-005：新任务自动分配编号 `TASK-YYYY-NNNN`。
- **异常处理**：创建失败时保留输入内容，toast 提示"创建失败，请重试"。

### F-003 跨团队任务关联

- **功能描述**：任务可标记"阻塞于"另一任务，被阻塞任务在看板上显示红色角标。
- **输入**：当前任务 ID、被依赖任务 ID（可跨看板）。
- **输出**：依赖关系建立；被阻塞任务卡片显示"🔴 被阻塞"角标。
- **前置条件**：两个任务均存在；不形成循环依赖。
- **业务规则**：
  - BR-006：循环依赖检测，发现时拒绝并提示依赖链；
  - BR-007：前置任务完成后，自动通知被阻塞任务负责人。
- **异常处理**：前置任务被删除时，依赖关系自动解除并通知双方。

## 4. 界面规格 / UI Specifications

### 4.1 看板主页

**布局**：顶部导航栏（团队切换、搜索、通知铃）+ 横向可滚动的看板列 + 右下角"+"快速创建按钮。

**元素**：
- 看板列：列头显示列名 + 任务数（如"进行中 (5)"），列内卡片纵向排列；
- 任务卡片：标题（2 行截断）、负责人头像、标签色条、截止日期（逾期红色）；
- 拖拽中：卡片半透明跟随，合法目标列高亮蓝色边框。

**交互**：
- 拖拽卡片到列之间：松手即流转，有 300ms 的落位动画；
- 点击卡片：右侧滑出详情抽屉（不跳转页面）；
- 快捷键：`n` 新建任务、`/` 聚焦搜索、`←→` 切换看板列。

### 4.2 任务详情抽屉

**布局**：右侧 480px 抽屉，分三区——标题区（标题、状态、负责人）、内容区（描述、子任务、评论）、侧栏（标签、截止日期、关联任务）。

**交互**：
- 描述支持 Markdown 实时预览；
- @提及：输入 `@` 弹出成员列表，被@者收到通知；
- 所有修改自动保存，顶部显示"已保存 HH:mm"。

## 5. 数据规格 / Data Specifications

| 数据项 | 类型 | 来源 | 说明 |
|---|---|---|---|
| task_id | string | 系统生成 | 主键，格式 `TASK-YYYY-NNNN` |
| title | string(100) | 用户输入 | 必填 |
| status | enum | 流转 | 待办/进行中/待评审/已完成 |
| assignee_id | string | 用户选择 | 可为空（未分配） |
| board_id | string | 系统 | 所属看板 |
| due_date | date | 用户输入 | 可为空 |
| blocked_by | string[] | 用户设置 | 依赖的任务 ID 列表 |
| created_at | timestamp | 系统 | 不可修改 |
| updated_at | timestamp | 系统 | 每次变更自动更新 |

## 6. 非功能规格 / Non-functional Specs

- **性能**：看板首屏加载 < 1.5s（1000 卡片以内）；拖拽流转端到端 < 500ms；WebSocket 消息延迟 < 200ms。
- **可用性**：核心操作（创建/流转）3 次点击内完成；支持键盘全操作。
- **可靠性**：数据每日自动备份，RPO < 24h；单机故障恢复时间 < 30 分钟。
- **安全**：密码 bcrypt 存储；会话 7 天过期；任务级权限校验（后端强制，不依赖前端）。
- **兼容性**：Chrome/Edge/Safari 近 2 个大版本；移动端提供响应式只读视图（v1.0 不做移动端编辑）。
